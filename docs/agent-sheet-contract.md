# חוזה הסוכן מול הגיליון

הגדרה של מה הסוכן קורא, מה הוא כותב, ומה הוא לא נוגע בו.

## חלוקת האחריות על העמודות

| עמודה | מי כותב | |
|---|---|---|
| `received_at` | הצינור | ISO 8601 |
| `wa_message_id` | הצינור | **מפתח ה-dedupe** |
| `from` | הצינור | מספר בפורמט בינלאומי בלי `+` |
| `name` | הצינור | שם הפרופיל בווצאפ, יכול להיות ריק |
| `type` | הצינור | `text`, `image`, `location`, `interactive`... |
| `text` | הצינור | גוף ההודעה, או הכיתוב במדיה |
| `media_id` | הצינור | מזהה להורדה דרך Cloud API |
| `location` | הצינור | `lat,lng` |
| `phone_number_id` | הצינור | המספר שקיבל |

| **`notes`** | **הסוכן** | טקסט חופשי |

## אוצר המילים של `status`

ריק נחשב `new`. הצינור כותב אותו ריק בכוונה.

| | |
|---|---|
| `new` | הגיע, טרם נבדק |
| `contacted` | נענה |
| `qualified` | ליד אמיתי |
| `quoted` | נמסרה הצעת מחיר |
| `won` | נסגר |
| `lost` | לא נסגר |
| `spam` | לא ליד |

## שני איסורים, ולמה

**אין לכתוב לעמודות הצינור.** בעיקר `wa_message_id`: זה המפתח ש-`Code.gs`
קורא לפני כל כתיבה. שינוי שלו הופך משלוח חוזר של Meta לשורה כפולה, כי ה-id
כבר לא יימצא בחיפוש.

**אין למחוק שורות.** אותה סיבה — שורה שנמחקה יוצאת מטבלת ה-dedupe. עדיף
`status: spam` או העברה ללשונית ארכיון. אם בכל זאת מוחקים, לעשות את זה על
שורות ישנות מחלון הניסיונות החוזרים של Meta, לא על טריות.

## איך לעבוד מול זה

**לקרוא:** לסנן על `status` ריק או `new`. זה התור.

**לעדכן:** להתאים לפי `wa_message_id`, לא לפי מספר שורה. שורות נוספות מגיעות
בכל רגע, ומספר שורה שנקרא לפני דקה כבר לא בהכרח נכון.

**מדיה:** `media_id` הוא מזהה, לא קובץ. הורדה דורשת קריאה ל-Cloud API עם
access token — לא נמצא בגיליון.

## מה שאין כאן

**היסטוריה.** הגיליון מתחיל מהרגע שה-webhook נרשם. לידים שכתבו לפני זה לא
יופיעו, ואין דרך למשוך אותם — ל-Cloud API אין קריאת היסטוריה.

**הודעות יוצאות.** נכנסות בלבד. אם תרצה את שני הצדדים, זה שדה webhook נוסף
ושינוי ב-`parse.js`.

**שרשור לשיחה.** כל שורה היא הודעה בודדת. לקוח ששולח שלוש הודעות יוצר שלוש
שורות. קיבוץ לפי `from` הוא עבודה של הסוכן.

## עמודות ששווה לשקול

לא הוספתי אותן — זו החלטה שלך, והוספה דורשת רק עריכת שורת הכותרות (הכותרות
נקראות בכל בקשה, בלי פריסה מחדש):

- `owner` — מי מטפל
- `next_action_at` — למעקב אחרי לידים שנשכחו
- `source` — כשיתווספו מספרים נוספים
